---
name: live2d-local
description: Prepare legally usable raster layers, editable mesh2d projects, bounded experimental MOC3 exports, and evidence-based local acceptance without host agents or uploads.
---

Read README.md and PROVENANCE.json first. Work with the user's own Codex, Claude Code, or another agent. Do not call a host runner, install packages, fetch dependencies, upload files, use credentials, create accounts, purchase licenses, or accept new SDK/Editor terms for the user. All bundled scripts use Node built-ins and run locally. If a requested step needs new licensing, permissions, network, or unsupported features, report the exact step and stop that step.

1. Establish asset ownership and inspect actual pixels/layer hashes. Read `studio/spec/PSD-GENERATION-CONTRACT.md` and its schema. Generate real missing eye/mouth/backfill material or report missing material. A composite duplicated into named layers is not automatic separation. Never mark visual approval from names alone. Preserve source originals and write to fresh output directories.
2. For a supported flat PSD, the browser editor can import PSD/PNG then save `studio-mesh2d` v1 JSON. For already exported, cropped PNG layers, supply `studio-png-layers` v1 (see schema and example), explicit role/offset/hash, asset rights, and declared parameters. Run `node scripts/cli.mjs materials layers.json new-source`. The starter grid/presets are approximations, not full character binding.
3. Run `node scripts/cli.mjs inspect project.mesh2d.json`. Edit base meshes and endpoint keyforms in a compatible browser editor, save, reopen, and retain the editable JSON. Keep source metadata and asset license separately. The `source` command packages editable JSON plus identity manifest without mutating it.
4. Check the current export capability matrix. Export only a flat project with exactly one effective animated 0–1 parameter: `node scripts/cli.mjs export project.mesh2d.json new-runtime ParamBreath`. Do not silently drop other animated parameters, masks, hierarchy, rotation, physics or unsupported source fields. The output is a genuine writer-generated candidate, not an accepted model yet.
5. If the user legally supplies the exact official Core identified in PROVENANCE.json, run `node scripts/verify-core.mjs project.mesh2d.json new-runtime ParamBreath /user/chosen/core.js new-core-report.json`. This checks consistency, native load, topology, UVs, layer order, defaults and source vertex interpolation. Reject unpinned uploaded JavaScript. Do not download Core automatically or redistribute it.
6. Browser acceptance must actually load model3 references and textures, compare visible pixels at 0/0.5/1 against source, play the declared motion, confirm vertex and visible motion, and save/reopen the runtime ZIP. A JSON header, file name, Core check alone, or static display is insufficient. Use a compatible local editor/runtime supplied by the user; a remote website is a separate destination decision for private inputs. Record the actual tested runtime/version and failures.
7. Deliver editable source and runtime ZIP separately, with hashes, asset/writer licenses, Core report and browser evidence. State which stages passed and which remain pending. MOC3-only input supports playback/parameter inspection; do not promise cmo3 recovery, full rig reconstruction, or lossless re-export. If a tool or safe GUI is unavailable, report it rather than bypassing it.
