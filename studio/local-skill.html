03 / HOW IT WORKS

像素、源项目与运行时，各走一步。

保留源工程，运行时作为另一份交付物。

A

已有分层 PNG 或 PSD

PNG 图层加角色 manifest 可直接进入流程。已有 PSD 可经浏览器支持的平面 PSD 导入器保存为 mesh2d；CLI 不解析 PSD。

B

单张图片 / PNG

先用你实际可用、已授权的图像工具分层并补全遮挡区域，再检查真实 RGBA 图层。PSD 是可选交换格式，内部可以一直用 PNG + manifest。

  1. 01

    准备真实图层

    分割或生成部件，补出隐藏区域；没有工具则报告缺失步骤。

  2. 02

    记录角色与坐标

    role manifest 保存顺序、偏移、最终 PNG 哈希、许可与参数语义。

  3. 03

    网格与关键形

    依据 alpha 支持范围生成规则网格，建立并检查两个端点形状。

  4. 04

    保存可编辑源

    mesh2d JSON 保留图层、像素、网格与端点，供后续编辑和重开。

  5. 05

    有限 MOC3 写入

    实验 MIT 写入器生成真实 MOC3、model3.json、纹理图集与测试动作。

  6. 06

    验收与预览

    官方 Core 校验、源画面对比、参数组合、真实动作及 ZIP 重开。

没有分层或补图工具，也可以先试一个小演示。

single-demo 只让一张整图做呼吸形变，不拆层、不补隐藏区域，也不完成真实眨眼或嘴内部。把单 PNG 装进 PSD，仍然是一张整图。tool-request 只输出供现有工具使用的提示与数据协议，不自动执行生图。

为什么这样设计？

素材规范让工具之间能交接；共享画布坐标让各层对齐；可编辑源让你不用为一次修改丢掉工程；独立运行时包用于预览和部署。每一步都有可检查的文件，失败时能指出具体阶段。

参考 Bunraku §3、§5 与附录 G ↗ 的部件分类、RGBA 隐藏区补全、alpha 几何、跨层协调关键姿态和运行时插值思路。本技能以现有图像工具或手工素材、确定性网格和预设替代论文的训练组件；它不是论文模型或复现实验，也不捆绑论文图片、权重或数据。

当前能够导出的边界

  • 1–4 个独立运动参数每个网格最多一个动态参数；一个参数可以驱动多个网格。
  • 扁平 ArtMesh、线性端点最多16个可见网格、8192总顶点、4096像素纹理图集。
  • 同网格叠加、旋转、层级、蒙版和物理尚未支持超出边界会拒绝，不静默丢动作；完整眼嘴、关节招手与 cmo3 工程不在当前输出范围。

05 / WHEN SOMETHING STOPS

遇到问题，先定位这一层。

反馈问题 ↗
下载了 ZIP，编辑器为什么打不开？

源项目 ZIP 先解压，再在“打开网格项目”中选择 project.mesh2d.json。运行时 ZIP 则在 Studio 的本地模型入口打开。技能 ZIP 是给本地助理和 Node 脚本用的，不是一个可直接播放的模型。

重复运行提示“Output already exists”，或 Node 运行失败？

每次选择一个全新的输出目录，原件和已有输出不会被覆盖。脚本需要已安装的 Node 22.12+。不支持的 PNG 类型，请用自己的本地图像工具导出为8位 RGB/RGBA、非交错 PNG；无需运行 npm install。

图层哈希、坐标或角色检查失败？

修改 PNG 后，重新记录最终文件 SHA-256；角色、偏移与画布尺寸须和真实文件一致。检查安全相对路径、唯一图层 ID 及明确的眼睛参数语义。重复整张合成图不能冒充拆层，视觉审批和隐藏区补全也不能由名字证明。

为什么眨眼像压缩、张嘴像拉伸，或导出被拒？

开放眼补丁或闭嘴线只提供近似形变，缺少的闭眼线、眼睑遮挡和口腔内部须先补素材。导出还会检查每个网格的动态驱动数、参数数量及结构边界。不要删掉失败检查来换取“成功”；先调整素材或网格绑定。

生成 MOC3 后，怎样确认真的可用？

Core 通过只是第一步。检查贴图方向、轮廓和遮挡，比较默认值、端点组合及中点（单参数为0/0.5/1），播放声明动作，并保存、重开 ZIP。空白、静态画面或文件头正确都不是完整验收。包中不含 Core；使用合法取得的匹配运行时。

反馈时说明你用了哪个包、系统与 Node 版本、失败阶段、错误文本和可分享的截图或合成复现。请勿将私有角色、密钥或未获授权的素材附到公开 Issues。
