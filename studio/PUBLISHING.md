# Publication and preservation

This workbench is added at `/live2d_models/studio/`. The homepage has one explicitly requested addition: a visible `./studio/` navigation link above the existing model viewer. The original 1,385-path baseline stays unchanged in `catalog/frozen-files.json`; `catalog/homepage-entry.json` records the homepage's original and revised hashes and byte counts against that original source commit. Verification accepts only those two exact homepage versions and checks the other 1,384 paths byte-for-byte, including all old models/assets and `index2.html`. The existing branch-based GitHub Pages build/deployment publishes the repository; `Static Studio checks` tests and builds the new code addition plus the recorded homepage replacement. Never deploy this incremental artifact as a complete Pages site.

The publisher states they already hold Live2D official written approval covering this arbitrary-local-model browser workbench and has explicitly authorized publication (2026-10-06). On 2026-10-06, the publisher explicitly approved the official download page’s Proprietary and Open Software License agreements, and its consent checkbox was selected before the official hosting URLs were used. This application approval does not grant redistribution rights for individual models.

The addition contains no Core, vendor renderer, model binaries, textures or private import fixtures. The original renderer and the Core for MOC3 versions 1–3 retain their same-site URLs. Newer MOC3 versions reference the official Cubism 5.2 hosting branch recorded with a tested integrity pin in `v2/runtime.json`; no new Core binary is included. Existing model references retain their original URLs. The generator creates code-only embed downloads locally in the browser. A visitor may separately confirm deployment rights for their own imported package and include those supplied files in a local download; neither import nor download uploads anything. No repository model archive or server download endpoint is created. Model-specific rights remain shown in the advanced catalog. BYOK keys are held only in browser memory and sent only to the endpoint explicitly trusted by the visitor. Own-backend mode keeps the supplier key on the site owner's backend and sends no browser Authorization header.

New content is limited to `studio/`, `v2/`, catalog metadata, verification/build tools and the recorded homepage navigation addition. The original homepage's viewer code and resource URLs remain unchanged. No old assets, Pages publishing source, custom domain, environment policy, or Actions permissions are changed. The full-copy release gate remains blocked because model redistribution has not been authorized.

The interface uses tabs without history routes. `studio/404.html` is a workbench fallback file; the existing site's global 404 and root viewer route remain in place. The homepage entry is an ordinary link, not a redirect.
